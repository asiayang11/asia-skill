# 构图与提示词

## 先填写内容蓝图

```text
主题：
受众与使用场景：
输出：成图 / 提示词 / 可编辑文件
尺寸或比例：默认 16:9
标题：
副标题：
一句话结论：
必须保留的术语、数字与限定条件：
版式：对比 / 流程 / 结构 / 概念解释
各区块准确文案：
关系：起点 → 终点；箭头标签；是否反馈
可选装饰：
```

## 构图选择

| 类型 | 结构 | 适用内容 |
| --- | --- | --- |
| 对比 | 上方标题；粉、蓝两列纸框；底部统一结论卡 | 两种方案、优化前后、优缺点 |
| 流程 | 3–6 张编号纸卡；明确箭头；侧边一张提醒便签 | 任务步骤、系统处理链路 |
| 结构 | 一个核心对象；3–5 个有标签的模块；真实关系连线 | 系统架构、组成和分工 |
| 概念解释 | 一个具体例子；2–4 张机制卡；最后一句结论 | 原理科普、误区澄清 |

技术架构中模块过多时拆图；不要因风格模板限制实际节点或连线。有关具体数据的曲线、柱状图、数量与比例使用确定性绘图实现。

## 生成模板

替换所有花括号，删除未用部分，再交给图像工具。需要参考图时从本技能目录解析 `assets/style-reference.png`，不要假设原始上传路径仍存在。

```text
制作一张 {比例/尺寸} 的中文说明图，主题是「{主题}」，面向 {受众}。
参考图只提供视觉风格；重新绘制当前主题，不复制原图文字、技术结论、签名或特定构图。

视觉：暖米色旧纸底，淡纤维纹理；黑色手绘墨线，略有自然不规则感；彩铅和蜡笔质感；低饱和珊瑚粉、灰蓝与向日葵黄；手账纸卡拼贴，轻微卷角，克制的浅阴影。整体温柔、亲切、信息清楚。使用黑色手写感中文大标题和黄色横涂划线，正文清楚可读。

构图：{具体布局和阅读方向}。
精确文案：
- 标题：「{标题}」
- 副标题：「{副标题}」
- {区域一，逐项写出所有需要出现在图中的文字}
- {区域二}
- 底部结论：「{结论}」
连线：{明确节点起止、箭头方向及标签}。

装饰：{2–3 类装饰及其位置}。装饰只占边缘空位，不覆盖文字，不形成额外流程节点。保持纸卡内部干净，大小层级清楚，充分留白。

约束：准确呈现以上文案与关系，不添加未经提供的统计数字、优势或品牌。不生成乱码、伪英文、重复文字；不使用冷白商务模板、矢量图标混搭、霓虹、玻璃效果、写实 3D、厚重阴影；不堆满花草，不将正文缩得难读。
```

提示词能提高文字准确性，但不能保证模型无错。需要准确的长中文、公式、数据或复杂拓扑时，生成无文字的插画底图，再用确定性工具排字、绘图和连线；或直接使用 SVG/HTML/CSS 实现。不要用同一个提示词无限重试。

## 可复用请求示例

- 「使用 $draw-cozy-explainers 解释 RocksDB 的 WAL，只讲一次写入的过程，做一张横向说明图。」
- 「使用 $draw-cozy-explainers 对比单 Agent 和多 Agent，使用我提供的材料，不添加性能数字。」
- 「使用 $draw-cozy-explainers 解释 HyperLogLog，只给提示词，不生成图片。」
- 「使用 $draw-cozy-explainers 把这个迁移流程做成可编辑 SVG，保留所有节点和条件。」

收到仅提示词请求时，交付填好当前主题的模板，不交付空模板。收到用户只要视觉分析或技能修改的请求时，输出对应内容，不额外生成示例图。
